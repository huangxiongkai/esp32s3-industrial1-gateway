# ADR007 - 采集任务与网络生命周期解耦

- **状态**：已采纳
- **日期**：2026-06
- **涉及里程碑**：M8（Step 5 系统集成时发现）

## 一、背景与问题

M5 时代的状态机采用"采集跟随网络生命周期"的设计：

- `handle_mqtt_conn()` 收到 `MQTT_CONNECTED` 才启动 `poll_scheduler` 和 `app_task`
- `handle_running()` 任意一条回退路径（WiFi 断 / MQTT 断）都会调用
  `poll_scheduler_stop()` + `app_task_stop()` 停掉采集与业务任务

该设计在当时成立：没有缓存层，断网期间产生的数据无处可去，停止采集是省事且语义清晰的选择。

M8 引入 cache_task（store-and-forward 闸门）后，前提变了：

1. Modbus 采集走 RS485 本地总线，**与网络状态无关**，断网期间传感器数据依然可读
2. 断网期间产生的数据正是断网续传要保护的对象——若断网即停采集，
   Flash 缓存退化为"只覆盖断连瞬间队列里的几条消息"，M8 价值缩水约 90%
3. Step 6 联调矩阵 T2（断网后 pending 每 2s +1）在该设计下根本不会发生

同时发现旧设计的一类隐患：每次重连成功都 `app_task_start()` 新建任务，
依赖回退路径的 stop 精确配对；任何一次 stop 未执行到（异常路径、重启前的窗口）
就是任务泄漏。

## 二、候选方案

### 方案 A：保持现状，仅补 set_online 接线

断网仍停采集，cache_task 只兜住过渡窗口内的消息。

- 优点：改动最小（state_machine 只加两行 set_online）
- 缺点：断网期间无数据采集，缓存层名存实亡；T2 场景无法通过
- **否决**

### 方案 B：采集与网络解耦，启动一次永不停止（采纳）

- `handle_init()` 队列创建后一次性启动 cache_task、poll_scheduler、app_task
- CONNECTED 分支只调 `cache_task_set_online(true)`
- 两条回退路径只调 `cache_task_set_online(false)`，删除 stop 调用
- 网络栈（WiFi/MQTT client）仍由状态机按原逻辑启停

优点：

1. 断网期间采集照常，消息全部落盘，T2 预期成立
2. 消除 start/stop 配对泄漏隐患（只 start 一次，无配对可言）
3. 状态机职责更纯：只管网络栈的连与断；"网络是链路问题，不是业务问题"

缺点 / 已知现象：

1. 开机后 WiFi 连上前，app_task 产生的消息会先写入 Flash，上线后补传——
   云端在上线瞬间收到几条"刚开机"的数据，属 at-least-once 正常表现，无害
2. `poll_scheduler_stop()` / `app_task_stop()` 在状态机中不再有调用点
   （函数保留，供将来系统关机 / 低功耗场景使用）

## 三、最终决策

采用方案 B。判定依据：**采集的依赖项（RS485、设备表、队列）全部在 handle_init
就绪，与 WiFi/MQTT 零依赖**，技术上无任何障碍；且这是 M8 断网续传目标成立的
必要条件，不是可选优化。

## 四、影响范围

| 文件 | 改动 |
|:---|:---|
| `main/app/state_machine.c` | 新增 `#include "cache_task.h"`；handle_init 尾部新增三个启动；删除 `s_app_task_handle` 变量；CONNECTED 分支瘦身为 set_online(true)；两条回退路径瘦身为 set_online(false) |
| `main/app/app_task.c` | 不改（app_task_stop 保留但状态机不再调用） |
| `main/scheduler/poll_scheduler.c` | 不改（poll_scheduler_stop 同上） |
| `main/app_main.c` | 不改（队列注入模式，业务任务由 handle_init 启动） |

## 五、改后生命周期（一句话版）

```
INIT:    cache_task / poll_scheduler / app_task 一次性启动
连网中:  online=false → 消息写 Flash
RUNNING: set_online(true) → 直发云端 + 积压限速补传
断网:    set_online(false) → 采集不停，消息转写 Flash
```
