# ADR002: Device Manager 与 Poll Scheduler 职责分离

## 状态
已采纳

## 背景
系统中需要管理设备状态和数据，同时需要按周期轮询采集数据。需要决定这两个职责放在同一个模块还是分开。

## 决策
将设备数据管理与轮询调度分为两个独立模块：
- **Device Manager** — 只负责设备表的增删改查、在线/离线状态维护
- **Poll Scheduler** — 只负责按周期触发 Modbus 采集，并调用 Device Manager 更新数据

## 备选方案

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| 职责分离（采用） | 单一职责、独立可测、灵活调度 | 多一个模块，接口稍多 |
| 合并为一个模块 | 代码量少、调用直接 | 职责混杂、难以独立调整轮询策略 |

## 为什么选择该方案
1. **单一职责原则：** Device Manager 是"数据库"，只存储和查询；Scheduler 是"调度器"，只控制轮询节奏
2. **灵活性：** 未来轮询策略可能变化（如不同设备不同周期），独立 Scheduler 更容易扩展
3. **可测试性：** 可以单独测试 Device Manager 的增删改查，不需要涉及轮询逻辑

## 影响
- 需要定义清晰的 Device Manager API 接口
- Scheduler 需要持有 Device Manager 的引用（通过函数调用，不直接访问内部数据）
