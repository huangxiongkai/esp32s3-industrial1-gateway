# ADR005 — W25Q64 分区布局：缓存区扩充至近全片

- 状态：已确认（2026-08-06，用户拍板）
- 相关里程碑：M8（W25Q64 断网续传）、M10（OTA）

## 背景与问题

W25Q64 容量 8MB。最初布局为"低 4MB 预留 + 高 4MB 缓存区"，
离线缓冲仅约 3 小时。复盘时发现低 4MB 没有确定的强需求：

- 系统事件日志（Power On / WiFi Connect / Device Offline 等）几百条即可，64KB 足够
- M10 OTA 采用 esp_https_ota 流式下载，固件直接写入**模组板载 Flash** 的 ota_0/ota_1 分区，不占用外部 W25Q64

即预留区大部分空间闲置，而缓冲时长是断网续传的核心指标。

## 候选方案

| 方案 | 布局 | 缓冲时长 | 优点 | 缺点 |
|:---|:---|:---|:---|:---|
| A. 维持对半分 | 缓存 0x400000~0x7FFFFF（4MB），低 4MB 预留 | ~3 小时 | 预留空间大，未来灵活 | 核心指标弱，预留区实际无强需求 |
| B. 缓存扩至近全片 | 日志区 0x000000~0x00FFFF（64KB）+ 缓存 0x010000~0x7FFFFF（~7.94MB） | **~6 小时** | 缓冲翻倍；改动仅一个宏 | 未来若需大块外部 Flash 用途（如固件暂存式 OTA）需重新规划 |

## 最终决策

采用 **方案 B**：

```
0x000000 ─ 0x00FFFF   事件日志区（64KB，M8 附带功能）
0x010000 ─ 0x7FFFFF   离线数据环形缓冲（32512 条 × 256B ≈ 7.94MB）
```

## 决策理由

1. OTA 走板载 Flash，外部 8MB 无预留刚需——闲置容量应投给核心指标
2. 0x010000 天然是 4KB/64KB 对齐边界，环形缓冲的扇区逻辑零改动
3. `CACHE_MAX_ENTRIES` 由地址宏推导，只需改 `CACHE_START_ADDR` 一处
4. 简历口径同步升级："断网 3 小时" → "断网 6 小时内数据零丢失"
