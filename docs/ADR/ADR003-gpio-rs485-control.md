# ADR003: RS485 方向控制采用 GPIO 软件控制而非硬件 RTS

## 状态
已采纳

## 背景
MAX3485 的 DE/RE 引脚需要控制收发方向切换。ESP32-S3 的 UART 外设支持硬件 RS485 流控（RTS 引脚自动切换），但本方案选择了 GPIO 软件控制。

## 决策
采用普通 GPIO（GPIO8）软件控制 MAX3485 的 DE/RE 方向切换，不使用 ESP32 硬件 RTS 流控【后续任务完成后可以尝试升级】。

## 备选方案

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| GPIO 软件控制（采用） | 引脚灵活、不依赖 UART 硬件特性、移植性好 | 需要手动管理时序 |
| 硬件 RTS 流控 | 自动切换、不需要软件干预 | 引脚固定、部分 ESP32 变体不支持 |

## 为什么选择该方案
1. **通用性：** GPIO 软件控制适用于任何 ESP32 变体和任何 UART 外设
2. **学习价值：** 手动管理收发时序有助于理解 RS485 半双工通信原理
3. **面试价值：** 可以展示对硬件时序的精确把控（`uart_wait_tx_done` 的使用）

## 影响
- 发送前必须拉高 GPIO7，发送完成后必须拉低
- 必须使用 `uart_wait_tx_done()` 等待发送完成再切换方向，否则最后一字节会被截断
